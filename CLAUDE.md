# msgs — agent notes

Rust + ratatui terminal client for iMessage on macOS.

## Layout
- `src/main.rs` — thin binary: clap entry, terminal setup/restore, event loop
- `src/lib.rs` — the crate everything else lives in, so `tests/` can drive it headlessly
- `src/app.rs` — `App` state, `Focus`, `Action`, the single `update()`; `keymap` → `update` → `ui` is the only input path
- `src/config.rs` — optional `~/.config/msgs/config.toml`; never fatal, problems become warnings
- `src/theme.rs` — named color slots (mockup palette, plus `Theme::light`), `Base` (dark / light / system / terminal, from `[theme] base`, `--theme`, or `Ctrl+T`), `system_is_dark` (`defaults read -g AppleInterfaceStyle`), `query_terminal` (OSC 10/11 on stdin, asked once by `main` after the alternate screen is up) and `Theme::terminal` (the palette mixed between the terminal's own bg and fg), overridable per slot from config
- `src/keymap.rs` — focus-sensitive key → `Action`; `BINDINGS` also feeds the help modal, and `SHORTCUT_BAR` is the footer's hints while an overlay is up
- `src/db/` — read-only access to `chat.db` (rusqlite + `imessage-database` for typedstream and `NSKeyedArchiver` parsing); `chat::merge_by_address` folds the per-service `chat` rows for one address into one conversation, so a `Chat` carries `Chat::rowids` (every member row, `Chat::rowid` — the row with the newest message — first, and `Chat::rowid_set` / `Chat::owns` to read it) and every query keyed by a chat rowid takes the whole set; `message::LinkPreview` is the rich-link card Messages already stored in `message.payload_data` (`parse_link_preview`, gated by `Db::set_link_previews` and `Schema::link_preview`)
- `src/ui/` — ratatui widgets: chat list, conversation, composer (a rule and a prompt, no box; `composer::rows` is the one word-wrap of the draft that its height, its drawing, the cursor, and a click all read), palette, `filepick` (the `@` list standing on the composer), help, `db_error` (the first-run surface), `notice` (the copy line above the composer), `status` (the one footer: `composer::context_hints` on the left, the segments or a toast on the right); `ui::compute`, `chat_list::Shape`, `conversation::Scroll`, `conversation::thumb`, `conversation::Selection` (the mouse drag: linear like a terminal's own, tinted into the buffer with `bg_selection`, the blue that is the one non-gray background, read back off that same buffer on release by `selection_text` when it is one row, and copied as `App::transcript` — `Name: body` per message under it, via `selected_messages` — when it is more, and kept on screen afterwards — `Selection::follow` slides it with the words when the view scrolls or the copy notice takes the bottom row, and only `Esc`, the next click, a new conversation, a pane of a different width, or scrolling every bit of it off screen takes it down), and `ui::message::block` are pure layout functions with tests, and `ui::format` holds the string helpers (relative times, previews, wrapping, truncation)
- `src/media.rs` — attachments as pictures: `fit` (pure cell arithmetic), `Images` (the measure/encode cache, `ratatui-image` under it), HEIC through `sips` into `~/Library/Caches/msgs/attachments`, `s` copying a file to `~/Downloads`, and GIFs that move — `is_animated`, `reel` (frames and delays, capped at `MAX_FRAMES` and `MAX_FRAME_BYTES`), `encode_reel` and `Animation`, decoded and encoded on the same worker thread the conversions run on and played by `Images::next_due` / `Images::advance` off `App::next_animation_due` / `App::tick_animations`; only what `Images::begin_frame` and `Images::render` say is on screen is ever stepped
- `src/paste.rs` — what a bracketed paste is: `tokens` (escapes and quotes), `path_of` (`file://`, `~`, absolute only) and `dropped_files`, all pure — the home directory and "is this a file" are handed in. `App::on_paste` turns a drop into `App::attached`, the composer's chips, and anything else into typing
- `src/shell.rs` — the clipboard (`pbcopy`, then OSC 52), the browser, and `open` for an attachment — `opener` picks between `open` and Quick Look (`qlmanage -p`, which plays a GIF where Preview.app pages through it); the only things msgs asks the rest of the machine to do
- `src/send.rs` — outbound messages via `osascript` → Messages.app; `Presence`, the timed yes/no probe behind the status line's Messages.app segment (`pgrep`) and, via `watching_with`, the system-appearance probe; plus `Pending`, the optimistic echoes. Tapbacks are read and drawn, never sent
- `src/watch.rs` — live updates: `notify` on the directory `chat.db` lives in, debounced, with a 2s timer as the fallback; `App::on_db_change` does the re-reading
- `src/search.rs` — the FTS5 message index at `~/Library/Application Support/msgs/index.db` (never inside chat.db): a worker thread builds it, tops it up from the live-update stream by `ROWID`, and answers `MATCH` queries
- `src/seen.rs` — the local read state: `~/Library/Application Support/msgs/seen.json`, a per-chat floor of unread already shown here; `Seen::apply` sets `Chat::unread` from `Chat::unread_count`, `Ctrl+U` marks all seen or gives it back, and Messages.app's own flags and badge are never touched
- `src/contacts.rs` — names for handles: the macOS AddressBook stores read read-only, normalized phone/email keys, and the stamped cache at `~/Library/Application Support/msgs/contacts.json`; `Contacts::apply` hangs a `Name` on every `Handle`, which is how names reach every pane at once
- `src/pins.rs` — which chats Messages.app has pinned: `~/Library/Preferences/com.apple.messages.pinning.plist` read read-only through the `plist` crate (`pD` → `pP` the pinned entries, `pZ` the group table), addresses normalized the way `contacts` normalizes them and groups matched on `guid` / `chat_identifier` / `group_id` / `original_group_id`; `Pins::apply` is the one place `Chat::is_pinned` is written outside SQL, and `db::chat::sort` is re-run after it because the pin state is not a column
- `src/jump.rs` — what the `Ctrl+K` palette matches and shows: the filter, fuzzy chat/people matching (`nucleo-matcher`), and the result rows with their highlight ranges
- `src/filepick.rs` — what the composer's `@` picker lists and matches: `triggers` (an `@` opens it only at the start of a word), the roots (`~/Downloads`, `~/Desktop`, `~/Pictures`, `~/Documents`, and the working directory — never anything under `~/Library`, never a hidden file, one name per root), one capped `read_dir` per directory newest first, the query as a path (`split`, `scope_for`, `descend`, `ascend`), and `filter`, the fuzzy pass (`nucleo-matcher`)
- `docs/mockups.html` — the design target; match it
- `docs/screenshot.txt` — the frame `docs/MANUAL.md` (and the README, until a video replaces it) embeds, written by `tests/screenshot.rs` from the synthetic fixture (`TZ=UTC UPDATE_SCREENSHOT=1 cargo test --test screenshot` regenerates it, and it also checks the block embedded in the manual); never a frame of a real `chat.db`
- `docs/MANUAL.md` — the long-form docs; the README stays short
- `tests/docs.rs` — the README's key table against `keymap::BINDINGS`, in both directions, so a binding cannot be added to one and not the other
- `tests/fixtures/*.db` — gitignored, built once from `tests/fixtures/mod.rs` and then cached; delete them after changing the fixture schema or every db test fails with "no such column". `fixtures::link_database` is a separate small database for link previews (its picture is the gitignored `tests/fixtures/*.pluginPayloadAttachment`), so the shared fixture's conversations stay exactly what every other test reads
- `tests/perf.rs` — the budgets, against `fixtures::perf_database` (200k invented messages): cold start under 300ms, a keystroke-to-frame under 16.6ms, a page under 25ms, under 150MB resident. Stated for `--release`; a debug run gets `SLACK`× the number
- `packaging/msgs.rb` — Homebrew formula stub; URL and sha256 are placeholders until a `v*` tag is pushed
- `.github/workflows/` — `ci.yml` (fmt, clippy, build, test, `--check` on macOS) and `release.yml` (both targets, `lipo` into a universal binary, tarball plus checksum on a `v*` tag)

## Rules
- Never write to `chat.db`. Open it read-only (`?mode=ro` / `OpenFlags::SQLITE_OPEN_READ_ONLY`), and copy to a temp file if a lock blocks reads.
- Message content is private. Do not print message bodies, phone numbers, or names to logs, test output, or commit messages. Tests use a fixture DB under `tests/fixtures/`, never the real one — including `fixtures::address_book`, the synthetic Contacts store; never the real `~/Library/Application Support/AddressBook`.
- A person is named in one place: `Contacts::apply` fills `Handle::name`, and every pane reads `Handle::display_name` / `Handle::short_name`. Do not resolve a name inside a widget.
- Pinning is read, never written. `~/Library/Preferences/com.apple.messages.pinning.plist` is opened read-only and never modified or copied, and `Pins::apply` followed by `db::chat::sort` — in `App::apply_pins`, called from `reload_chats` — is the only path that puts pinned chats first. A schema that does have `chat.is_pinned` still gets its answer from SQL, because `Pins::off` writes nothing.
- Unread is counted in one place too: `Chat::unread_count` is the database's own answer and never moves, `Seen::apply` is the only thing that writes `Chat::unread`, and every badge, dot, and status-line total reads that. Messages.app's read flags and Dock badge cannot be cleared from here — say so rather than pretending otherwise.
- `cargo build`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, and `cargo fmt --check` must pass before a commit.
- The release profile is what ships and what the perf numbers are stated against: `lto`, one codegen unit, stripped, and panics still unwinding so the hook in `main` can put the terminal back.
- Keep the UI calm: no feature creep beyond the mockups. One accent (`accent_me`): your own name, the selected chat's edge, an unread chat's time, links, the focused border. No rails, no bands, no per-person colors, no bold — a name is a regular-weight label in `text_secondary` (`You` in the accent), and the body in `text_primary` is the brightest thing on the line; the header title is regular weight too. The clock lives in `ui::message::TIME` columns at the right edge of the first row of every block; `meta_text` is only what goes under a message besides the clock, and a block has no meta line when that is nothing. The name is a column: every row after the first of a message — wrapped lines, chips, pictures (`ImageSpot::column`, measured at `ImageSpot::room`), the meta line — is set in past it. Consecutive messages from one person within `RUN_GAP_SECONDS` are a run (`Ctx::continues`): the name once, the rest in that column, a blank row (`Block::gap`) above each run and each day. The chat list is `CHAT_ROWS` (3) per chat, the third blank, under `HEAD_ROWS` (the filter line and a blank). Below `MIN_WIDTH_FOR_CHAT_LIST` the list is a screen, not a pane: `ui::list_screen` / `App::list_screen` — it is drawn instead of the conversation while `Focus::ChatList`, `Ctrl+B` and `Esc` swap it in and out, and `show_chat_list` only governs docking. Focus and the selected chat are grays (`border_active` is a brighter gray, the selected chat is `bg_highlight` alone); only the mouse selection is blue (`bg_selection`), so a drag reads like a terminal's own; the composer is a rounded box; the chrome is `Panes::status`, the right end of the header row (or the filter line on the list screen), drawn last by `ui::status`: `unread_label` or a toast, then `? help`, nothing else — no bottom bar, no rule, no row of its own. The one exception is the copy notice: `Panes::notice`, a single right-aligned line in `text_secondary` (`copied N chars to clipboard`, `1 char` in the singular) drawn by `ui::notice` on a row `ui::compute` takes off the bottom of the conversation directly above the composer, and only while `App::notice` is live — `NOTICE_TTL` (3s), the next keystroke, or the next copy, whichever comes first, with `App::next_wake` waking the loop to take it down. `render_header` stops short of `status::reserved`; `Panes::screen` is how the app learns the terminal's width; overlays (help, palette) are gray-on-gray, keys bold in `text_secondary`, `fuzzy` hits bold without a hue; the header is the name and address, no counts. `Ctrl+N` is global: outside the palette it opens it with a toast, inside it — or `Enter` on an address that matched nothing — starts the chat; while a draft is open the header shows the address, and `adopt_draft` hands `reload_chats` the new row to anchor on once Messages has created it. A run says its clock once per minute (`Ctx::same_minute`); received tapback chips are gray text, no background. Clocks are twelve-hour (`ui::format::clock`, `TIME` = 8 columns).
- Nothing at startup is fatal. A failure becomes a warning on `Status::warnings`, which is toasted once and then listed under `NOTES` in the help modal; an unreadable `chat.db` becomes `App::db_error` and the full-screen `ui::db_error` surface, never an exit.
- `Focus::DbError` is never assigned to `App::focus`. `App::key_focus` reports it while `db_error` is set and no overlay is up, which is how the first-run surface gets its own keys without disturbing the pane focus the app goes back to.
- `--check` prints paths and counts only. No name, number, or message body may reach it.
- Chrome never covers a message. The day band is `Panes::day`, a row `ui::compute` takes off the top of the conversation, the copy notice is `Panes::notice`, a row it takes off the bottom (never the conversation's last one), and the scrollbar lives in the column `ui::message::MARGIN_RIGHT` keeps clear; none of them is painted over a block.
- The `?` modal opens a heading every time `BINDINGS` changes scope, so the table is grouped by scope and each scope appears exactly once. `tests/docs.rs` holds the README's key tables to that same table, so a new binding is added in one place and lands in three.
- msgs never opens a socket. A link preview is read out of the archive Messages already wrote; nothing fetches a page, an image, or a favicon.
- The `@` picker belongs to the composer, not to the overlays: `Focus::FilePicker` takes the keys while the draft keeps the cursor and every character typed, because the query *is* the run of the draft from the `@` to the cursor (`App::picker_query`). `Esc` leaves that run standing, which is how a literal `@` is had at a word start; a backspace past the `@` closes it; `Enter` queues the file on `App::attached`, lifts the run back out, and puts the cursor where the `@` was. `App::attached` is drawn as a chip per file above the draft and sent one message each ahead of the words. It is drawn like the palette and shares its `highlight`: gray on gray, hits bold in `fuzzy`, no new color and no dimming behind it. `App::picker_roots` is how a test points it at a temporary tree rather than at a home directory.
- Several pictures on one message are a set (`media::SET_ROWS`, 6, against `MAX_ROWS`, 10, for a picture on its own): `ui::message::block` counts what `Images::could_draw` says is a picture before measuring anything, asks `Images::cells_capped` at the lower cap, and flows the spots left to right in the name column (`Sheet`), wrapping like words. The cap is stable per attachment — an attachment belongs to one message — so the cache is keyed without it. Which one `o` / `s` act on is `App::attachment_at`, the message rowid and the attachment's position, read through `App::attachment_cursor` (and `Ctx::cursor`): `h` / `l` move it, a click on a picture sets it, and any other message is back at its first attachment; a set's meta line says `N photos · i of N · name · size`. `O` is `shell::open_paths`, one Quick Look with every file.
- A block's height and its drawing must come from one number. `ui::message::block` reserves rows for a picture from `Images::cells`, and `Images::render` draws into exactly those rows; never let the two compute a size separately. `ImageSpot::picture` (`Picture::Attachment` / `Picture::Preview`) is how both sides name the same file. A GIF is held to the same number: every frame is encoded at the size the still came back as, and a reel whose frames encode to anything else is thrown away rather than drawn, so a picture that starts moving can never change the height of the block it is in.
- A resize must not re-send a picture. `Images` files a measurement under the pane width, but the encoded pixels — a still or a whole GIF reel — are carried across to the new width whenever the measured size is unchanged (`Images::carry_over`), and the widths a drag passed through are dropped (`Images::forget_stale_widths`). On a kitty terminal re-encoding means re-transmitting, which is the flicker. The event loop matches: `main::wait_for` keeps draining while a resize burst is arriving (`RESIZE_SETTLE`) so a drag costs one frame, and no animation frame is stepped inside one.
