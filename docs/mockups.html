msgs · iMessage in the terminal · three surfaces

Msgs, an iMessage TUI

A reader with a send box, honestly scoped: read everything from chat.db, send text and files through Messages.app, tapbacks via imsg. Same visual grammar as the jot mockups — accent rail per sender, lighter band for your own messages, bordered composer, shortcuts bar — because it's the same Grok Build lineage. Names below are placeholders.

Surface 1 · default

Chats + conversation

Chat list on the left (recent-first, unread bold with a count, pinned on top), conversation on the right. Rail color: blue is you, green the other person; in groups each participant gets their own color. Tapbacks sit under the message as a chip. Images render inline with the kitty graphics protocol (Ghostty supports it); anything else is a file chip you can open.

Surface 2

Group chat — one color per person, threaded replies

Groups are where the accent rail earns its keep: each participant keeps a stable color across the whole thread, so you can skim who said what without reading names. A reply-to shows the quoted line above the message. Joins, renames, and "X reacted" events render as dim system lines instead of full blocks.

Surface 3

Jump palette — people, chats, and message search

Ctrl+K from anywhere. Type a name to switch chats; type more words to full-text search across all messages (SQLite FTS over chat.db text, built once on first launch, incremental after). Results show who, where, when, and the matched line. Enter jumps to that message in its conversation with it selected.

Under the hood

How each surface maps to the backend

NeedRust crate routeimsg route
Chat list, unread countschat, chat_message_join tables via imessage-databaseimsg chats --json
Message bodies (incl. attributedBody)built-in typedstream parserparsed by IMsgCore
Live updateswatch chat.db-wal with notify, re-query since last ROWIDimsg watch --ndjson stream
Send text / fileosascript to Messages.appimsg send
Tapbacks (send)not available without porting the helperimsg send --reaction
Inline imagesread attachment path from DB → kitty graphics protocol in Ghostty/Kitty/WezTerm; chafa fallback elsewhere
Full-text searchyour own SQLite FTS5 index next to the app, rebuilt incrementally from either source
Contact namesAddressBook SQLite (~/Library/Application Support/AddressBook) or contacts CLI; cache to disk

Order of work: surface 1 read-only → send box → surface 3 palette → surface 2 group polish → inline images → tapbacks. Read-only surface 1 alone is a useful app and is roughly a week of evenings with ratatui.
